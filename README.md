# Platform Control Project

Platform Control Project — это комплексная система автономного управления малогабаритной гусеничной/колёсной платформой Venom Light, предназначенной для выполнения парковых и вспомогательных работ.  
Проект объединяет картографию, навигацию, компьютерное зрение, датчики, телеметрию и исполнительные механизмы в единую архитектуру автономного движения.

## 🎯 Цель проекта

Цель — создать надёжную и полностью автономную систему, способную:
	•	безопасно передвигаться по заранее заданным маршрутам,  
	•	распознавать дорогу и держаться её контура,  
	•	корректно проходить перекрёстки,  
	•	выполнять развороты при потере дороги,  
	•	останавливаться перед препятствиями,  
	•	отображать своё положение и состояние в реальном времени,  
	•	управлять навесным оборудованием (3-й канал PWM / «B»),  
	•	собирать данные для последующего дообучения моделей.  

И всё это — с учётом реальных условий эксплуатации: неровности парка, перепады яркости, тени, сложные поверхности, ветки, люди, животные, погодные условия.

## 🧭 Основные компоненты системы

1. Картографический модуль  
	•	Использует заранее подготовленные карты (PNG + graph.json).  
	•	По клику на карту выбирается старт и цель.  
	•	Строится маршрут как последовательность точек (route_pts_px / route_pts_m).  
	•	Выделяются перекрёстки (узлы с ≥3 рёбрами).  
	•	Контрольные точки (КТ) рассчитываются по маршруту и используются для подсказок/логики движения.  

Задача модуля: дать роботу маршрут, по которому он должен двигаться.

2. Навигационный модуль  
Содержит:  
	•	прогрессию по маршруту (route_done_m / route_len_m),  
	•	расчёт положения робота на карте (robot_px),  
	•	определение направления движения (robot_heading_rad),  
	•	оценку расстояний до событий (КТ/перекрёстки/флаги).  

Задача: обеспечивать устойчивое движение вдоль маршрута и корректное переключение сегментов.

3. Модуль лидаров  
Использует данные от вращающегося лидара:  
	•	определяет наличие препятствий в секторе перед роботом,  
	•	вычисляет минимальные расстояния,  
	•	инициирует аварийную остановку при опасном сближении.  

Цель: предотвратить столкновения.

4. Камера и сегментация дороги (RoadSeg)  
Используется нейросеть для выделения дорожной поверхности:  
	•	определение контура дороги,  
	•	обнаружение её центра,  
	•	обнаружение развилок,  
	•	оценка «качества дорожности» (road score),  
	•	обработка потери дороги.  

Результат: робот понимает, где дорога (даже без разметки), и удерживается на ней.

5. Логика движения и стабилизации  
На основе маски дороги и маршрута система:  
	•	компенсирует смещение робота от центра дороги,  
	•	корректирует скорость и направление,  
	•	выбирает нужную ветку на развилках (сопоставление направления маршрута и направления «дороги»),  
	•	выполняет разворот при потере дороги.  

Цель: плавное и устойчивое движение по сложному рельефу.

6. Система управления моторами (Arduino)  
Реализована через Arduino Mega:  
	•	левый мотор — отдельный PWM (L),  
	•	правый мотор — отдельный PWM (R),  
	•	третий канал — вспомогательное оборудование (B).  

Система принимает команды от UI/контроллеров и переводит их в реальные PWM.

7. Пользовательский интерфейс (UI, PyQt)  
Графический интерфейс отображает и управляет:  
	•	картой и маршрутом,  
	•	позицией робота и направлением,  
	•	маской дороги и метриками,  
	•	лидарной визуализацией / safety stop,  
	•	состоянием системы (индикаторы),  
	•	панелью управления,  
	•	режимами: «Ровер», «КР», «Цель», «Траектория».  

Цель: дать удобный и понятный инструмент взаимодействия с платформой.

8. Система сбора данных (Dataset Capture)  
Во время движения:  
	•	фиксируются кадры камеры,  
	•	сохраняются снимки лидара,  
	•	записываются координаты и состояние.  

Эти данные используются для дообучения моделей распознавания дороги и улучшения автономности.

## 🧩 Новые возможности и актуальная логика (обновлено)

## Траектории и редактор маршрутов (Trajectory Map Editor)

В проект добавлен редактор траекторий, позволяющий быстро создавать маршруты «по кликам» в произвольном масштабе.  
Результат редактора:
	•	`<name>.png` — изображение траектории,  
	•	`<name>_points_pixels.json` — точки траектории в px,  
	•	`<name>_graph.json` — граф с `nodes/edges` + масштабом `m_per_px_x / m_per_px_y`.

Важно: масштаб хранится в graph.json, и при загрузке карты UI должен записать его в:
	•	`state.m_per_px_x`  
	•	`state.m_per_px_y`

Это устраняет «900 метров вместо 1 метра» и делает метры консистентными.

## Движение по траектории (Trajectory Mode)

В DrivePage есть режим движения по построенному маршруту (route), который:
	•	стартует движение и анимацию как обычный Start/Stop,  
	•	использует `route_pts_px` как геометрию маршрута,  
	•	внутри `_trajectory_tick()` оценивает необходимость поворота по локальной геометрии и heading,  
	•	шлёт команды на моторы через `motors_set(L, R, B)`.

Параметры управления:
	•	`state.pwm_base_us` — базовая скорость (обычно 1700–1900),  
	•	`Δ (delta)` — дифференциал поворота (L=base+Δ, R=base-Δ),  
	•	поворот инициируется заранее (в метрах, через масштаб карты),  
	•	логирование поворотов происходит по событиям START/turning/END, а не по частоте.

## Флаги КР и 3-й выход (B)

В режиме «КР» по клику на карту добавляются флаги, которые управляют 3-м выходом (B) при пересечении:
	•	первый флаг — B ON (зелёный, обычно 2000),  
	•	второй флаг — B OFF (красный, обычно 1500),  
	•	дальше чередование ON/OFF.

Важно:
	•	при пересечении флаг должен удаляться из `state.control_pts_px`, и соответствующий тип — из `state.control_pts_kind`, чтобы цвета не «пересчитывались заново» и не ломали порядок;  
	•	при клике в режиме «КР» НЕ должно отправляться на Arduino — управление B происходит только при пересечении флага.

## Масштаб карты и корректные метры

При загрузке карты масштаб берётся из graph.json:
	•	`m_per_px_x`, `m_per_px_y` (или из meta, если используется meta-обёртка)  

Записывается в:
	•	`state.m_per_px_x`, `state.m_per_px_y`  

Далее при расчётах используется `alpha_m_per_px` и/или м/px из state для перевода:
	•	px → m  
	•	радиусы поворота в метрах → px (через масштаб)

## 🚀 Почему этот проект важен

Платформа Venom Light должна:
	•	работать в реальном парке,  
	•	двигаться автономно среди людей,  
	•	корректно ориентироваться в среде,  
	•	не наезжать на препятствия,  
	•	уметь выполнять работу без оператора.  

Проект объединяет несколько технологий:
	•	робототехника,  
	•	компьютерное зрение,  
	•	навигация,  
	•	графовые алгоритмы,  
	•	машинное обучение,  
	•	ROS2,  
	•	управление железом,  
	•	инженерные решения по безопасности.  

В итоге создаётся компактная автономная система, готовая к реальному применению.
